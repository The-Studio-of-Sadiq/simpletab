## Setup

- Every SimpleTab action (115) is registered as a command in the "SimpleTab" category of the command palette.
- The inventory test renders every page and panel with enough data that their action buttons appear.
- The real-host test runs in Node, with no UI. It starts a `HostServiceImpl` on a SQLite file and wraps it in the app's own `TournamentStore`. Each command then runs through `executeAction` with no arguments, exactly as the command palette runs it: the command asks its questions, a scripted palette answers them, and the command runs against the host. After each command, the test reads the host's committed state back through the store.
- Laptop: 11th Gen Intel Core i7-1165G7 (8 threads), 16 GB, Node 24.21.0.

## Fixed while building the checkpoint

The step-b Draw, Allocation and Motions prompts did not yet follow the rule that a palette prompt never cancels without saying why. Those prompts are:

- the draw seed;
- the panel size;
- "Restore the previous draw" and "Restore the previous allocation", which asked for a typed change number;
- a blank motion text.

Now:

- The seed and the panel size ask again until the value is valid. The seed is offered pre-filled with a random number, as on the page.
- The restore commands pick a round whose draw or allocation this session generated. If there is none, the palette says so.
- A blank motion text is asked again.
