# M9 check: curated extensions

- **Date of the scripted run:** 2026-11-26
- **Build:** simpletab M9 step c, Theia 1.77.0, Electron 44.9.1; `npm run build -w packages/app` after `npm run rebuild -w packages/app`
- **Laptop:** Windows 11, 11th Gen Intel Core i7-1165G7, 16 GB

The milestone's checkpoint has two parts:

- `npm run e2e:extensions`, automated, below;
- this manual check, which asks whether each listed extension works in the built app.

Claude ran the manual steps in the built app through the Chrome DevTools protocol (`--remote-debugging-port`) and recorded what happened. Steps that need a person's judgement are left for the author.

## Setup

1. Save the pinned files: `npm run fetch:extensions`. It keeps them in `tools/e2e/fixtures/extensions`, outside git, after checking each SHA-256.
2. Install them in a test folder:
   - copy the files into a folder and start the app with `SIMPLETAB_EXTENSIONS_DIR` pointing at it, or use the Extensions page;
   - turn developer mode on (or use a paired staff laptop);
   - start the app with a workspace folder holding `teams.csv` (a few teams and speakers) and `notes.md` (a short note with a misspelt word of four letters or more).
3. Optional: set `SIMPLETAB_BACKEND_LOG` to a file to keep the backend's log. A relaunched or packaged app has no console.

## Automated: `npm run e2e:extensions`

Result: **pass** (4 tests). It checks that:

- each saved file is the extension the list names (the id and version in its `package.json`), and needs no VS Code API newer than 1.144, the version Theia 1.77 provides;
- every listed extension installs through the extensions service, both "from Open VSX" (the saved copy of the listed URL) and from a chosen file under another name, and only with a matching SHA-256;
- a file with one byte changed is refused when chosen, and ignored when copied straight into SimpleTab's folder;
- all of them load on a staff laptop and with developer mode on, and none on a laptop that may host;
- with them loaded, creating a tournament is refused while developer mode is off and allowed while it is on, and the host's status lists them.

## Changes to the list from this check

- **Removed: Markdown preview (`vscode.markdown-language-features` 1.95.3).** Its commands appear in the palette, but **Markdown: Open Preview** opened no preview in the scripted run. The backend and plugin-host logs gave no error, and the cause was not found. The list's own rule says an extension is listed only if it works in Theia 1.77, so it is off the list until someone finds why.
- **Added: Markdown language (`vscode.markdown` 1.95.3, MIT).** It is the Markdown language definition. Without it, `.md` files open as plain text, which is what kept the preview's commands hidden. It is useful on its own: highlighting, and it lets the spell checker treat notes as Markdown.
